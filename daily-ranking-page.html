自動公開ページ

自社商品が楽天のジャンル別デイリーランキングで何位だったかを、1枚のページで見られるようにしました。データの取得からページの公開まで、毎日人の手を介さずに更新されます。

技術スタックPython / BigQuery / GitHub
更新1日2回 自動公開
表示1〜1000位を対数で
課題と解決策

😰 Before（課題）

  • ランキングの推移を見るには、日付ごとにページを開いて探す必要があった
  • 毎朝の作業の中で手動更新していたので、忘れた日は古いままだった
  • 1位と数百位を同じグラフに描くと、上位の動きがつぶれて見えなかった
  • セール中にどの商品が駆け上がったのか、まとめて振り返れなかった

🎉 After（解決）

  • 毎日決まった時刻に、最新のランキングがページに反映される
  • 入賞カレンダーで、どの商品がどの日に入賞したかが一目で分かる
  • 縦軸を対数にして、1位付近の動きも数百位の動きも同じグラフで読める
  • セール期間のベスト順位と、駆け上がった商品を自動でまとめる

技術的なポイント

🤖 取得と公開を分けて無人化

データ基盤への接続は社内PCに、ページの公開はクラウドの自動実行に任せ、その間をGitHubで受け渡しています。クラウド側は届いたページをそのまま公開するだけなので、判断の余地がなく安定して動きます。

役割を分けて安定させる

📐 縦軸を対数にする

1位〜10位の動きと、100位〜1000位の動きは、桁が違います。普通の目盛りだと上位の変化がつぶれてしまうので、対数の目盛りにして、どの順位帯の動きも同じように読めるようにしました。

グラフの選び方

🕒 いつ時点のデータかを必ず表示

社内PCが止まっていた日は、ページが前日のままになります。その場合も「いつ時点のデータか」をページに表示しているので、古い数字を最新と取り違える事故になりません。

古さを隠さない

🔑 認証は既存の仕組みと共有

データ基盤への認証は、ほかのレポートと同じものを使っています。ツールごとに別々に持たせると、更新のタイミングがぶつかってほかのツールまで止まってしまうためです。

既存ツールを壊さない

💡 「忘れても更新される」が一番の価値

最初は毎朝の作業の中で更新していましたが、忘れた日はそのまま古くなっていました。人の作業に乗せず、決まった時刻に勝手に新しくなる形にしたことで、見たいときにいつでも最新が見られるページになりました。画面はダミーの表示例です。
