ANALYSIS

商品名変更
効果測定

商品名（タイトル）を変更した前後で、アクセス人数・転換率・売上がどう変わったかを自動で前後比較・可視化。 改善施策の効果を、感覚ではなく数字で検証できる仕組みを実現しました。

カテゴリ 効果測定・前後比較
技術スタック Python / BigQuery / Google Sheets / launchd
測定タイミング 変更14日後・30日後の2回
通知 毎朝 自動でSlack配信
課題と解決策

😰 Before（課題）

  • 商品名を変えても「良くなったのか悪くなったのか」が感覚でしか分からなかった
  • 変更前後の数字を毎回手作業で集計・比較するのが手間で、つい後回しに
  • セールやイベントで数字がブレて、商品名そのものの効果が見えづらい

🎉 After（解決）

  • 変更前後のアクセス人数・転換率・売上を自動で前後比較し、数字で判定
  • 店舗全体の伸び率と比べてセール・季節のノイズを補正、名前の純粋な効果を抽出
  • 14日後・30日後の2段階で毎朝自動チェックし、結果をSlackに通知

技術的なポイント

⚖️ 店舗全体比でノイズ補正

商品単体の数字だけ見ると、セールや季節要因で「名前の効果」と「時期の効果」が混ざってしまいます。同じ期間の店舗全体の伸び率と比べることで、商品名そのものの純粋な効果だけを抽出します。

相対比較ロジック

🕒 14日・30日の2段階判定

変更直後は初動やセールの偏りで数字がブレます。14日後は「経過観察」、30日後を「最終判定（維持／微調整／元に戻す）」と役割を分け、慌てて誤判断しない設計にしています。

2段階レビュー

🚦 セール汚染の自動保留

測定期間にセール準備の販売停止やSALE価格が重なると、数字は「名前の効果」ではなくなります。この条件を自動検知して判定を保留し、セール明けのきれいな期間で自動的に測り直します。

自動リカバリ

📈 BigQueryで正確に集計

アクセス人数・転換率・売上のデータはBigQueryから商品単位で正確に取得。変更前N日と変更後N日を同じ日数で切り出し、フェアな前後比較を実現しています。
